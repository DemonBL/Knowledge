# Domain Knowledge Hub — «Сховища знань та управління знаннями»

Тематична область: «Аналіз достовірності інформації». Хоптій Дмитро, ФЕІ-42, ЛНУ ім. Івана Франка.

Кожна лабораторна робота — в окремій гілці:

| Гілка | Лабораторна | Папка |
|---|---|---|
| `lab11` | ЛР 11 · Чат-бот на основі гібридного сховища (RAG + граф) | `lab11/` (+ залежність `lab10/` — корпус і пошук) |
| `lab12` | ЛР 12 · OLAP-куб на основі таксономії | `lab12/` |

Спільні утиліти — `common/hub_common.py`: підключення до Neo4j, запуск Ollama, журнал викликів LLM за протоколом «LLM-експерт».

## Середовище

- Python 3.11+, `pip install -r requirements.txt`.
- Ollama з моделями `qwen2.5:7b` і `gemma3:4b` — локальні LLM, ключі API не потрібні.
- Neo4j 5.26 Community (для ЛР 11).

Розташування інструментів задає змінна `KMS_TOOLS`; пароль Neo4j — змінна `NEO4J_PASSWORD`. Секрети в репозиторій не потрапляють (див. `.gitignore`).

## Використання генеративного ШІ

Відповідно до вимог курсу LLM використано як експерта: він пропонує чернетки (код, запити, тести, тексти), а студент їх перевіряє. Журнали взаємодії — `labNN/llm_log/`, таблиці тверджень зі статусами перевірки — `labNN/claims/claims.csv`, декларація — у звітах.
