# ЛР13 · Схема витягу та інструкція розмітки (версія 2)

Предметна область: «Аналіз достовірності інформації» (Domain Knowledge Hub). Схема спирається на класи онтології ЛР 6–7: Публікація, Твердження, Наратив, Акаунт-автор, Офіційне джерело, Фактчекер, Метод верифікації, Ознака дезінформації. Код схеми: `src/schema.py`.

## 1. Типи сутностей (8)

| Тип | Визначення | Приклади | Контрприклади (не цей тип / не розмічати) |
|---|---|---|---|
| ORG | організація, проєкт, державний орган, фонд, компанія без власної платформи | StopFake, Центр протидії дезінформації, ВООЗ, МОЗ України, Microsoft | «Facebook» → PLATFORM; «ЗМІ», «спецслужби» (загальні) — не розмічати |
| PERSON | названа особа | Поліна Лисенко, Mark Miller | «Президент України» без імені; нікнейми приватних користувачів |
| PLATFORM | соцмережа, месенджер, відеосервіс або їх загальна назва | Telegram, Facebook, YouTube, «соціальні мережі», «месенджери» | «Інтернет», «сайт», «вебресурс» |
| PHENOMENON | вид дезінформації, маніпуляції чи шкідливої інформаційної активності | фейк, дипфейк, пропаганда, фішинг, тролінг, соціальний бот | прикметники («пропагандистський»); мітки вердиктів «фейк» після «вердикт VRD-..» |
| METHOD | метод, технологія, інструмент або стандарт перевірки чи створення контенту | аналіз EXIF, геолокація, штучний інтелект, TensorFlow | назви версій специфікацій (Exif Print, DCF 2.0); формати файлів |
| LOCATION | країна, місто, регіон, місце | Україна, Одеса, Майдан | частина назви організації («МОЗ України») |
| DATE | дата, місяць, рік, період, строк | 2 березня 2014 року, 2017 року, 12 годин | номери документів («№ 106») |
| CASE_ID | ідентифікатор бази знань Hub і псевдонім акаунта | ACC-015, CLM-13, NAR-03, VRD-10, OFF-04, RULE-1, Ф-04, «Анонімний Telegram-канал #1» | — |

## 2. Типи відношень (10)

| Відношення | Голова → хвіст | Приклад (цитата) | Контрприклад |
|---|---|---|---|
| FOUNDED_ON | ORG/PLATFORM → DATE | «stopfake.org запустили 2 березня 2014 року» | дата призначення керівника — не FOUNDED_ON |
| PART_OF | ORG/CASE_ID → ORG/CASE_ID | «робочий орган Ради національної безпеки…»; CLM-17 → NAR-03 | співпраця двох незалежних організацій → COOPERATES_WITH |
| LEADS | PERSON → ORG/PLATFORM | «керівницею Центру призначено Поліну Лисенко»; «засновник Facebook Марк Цукерберг» | особа лише згадана поруч з організацією (Ілон Маск у W18) |
| COUNTERS | ORG/PLATFORM/METHOD → PHENOMENON | «спільно протидіють … дезінформації»; «була заборонена сайтами… Reddit» | організація лише «повідомила про» явище; партнерство «у сфері боротьби з фейками» — це COOPERATES_WITH між партнерами **і** COUNTERS кожного партнера, а не лише одне з них (уточнення v2.1 після аналізу κ) |
| COOPERATES_WITH (симетричне) | ORG/PLATFORM ↔ ORG/PLATFORM | «StopFake стали партнером Facebook»; фінансування проєкту | спільна згадка в переліку без дієслова співпраці |
| SUBTYPE_OF | PHENOMENON/METHOD → PHENOMENON/METHOD | «Фішинг — один з різновидів соціальної інженерії»; підрозділ «Види соціальних ботів» | синоніми («дипфейк або діпфейк») — одна сутність |
| SPREADS | ORG/PERSON/CASE_ID → PHENOMENON/CASE_ID | «поширювали … державні органи РФ»; «першоджерело: PUB-067 від ACC-001» → ACC-001 SPREADS CLM-17 | репост бот-акаунтів без кодів |
| SPREADS_VIA | PHENOMENON/CASE_ID → PLATFORM | «Боти часто працюють у групах (Telegram, Whatsapp, Viber)» | платформа, що забороняє явище → COUNTERS |
| REFUTES | ORG → CASE_ID | «Спростовано офіційним джерелом МОЗ України (OFF-04)» | вердикт VRD-xx (не є ORG) |
| USES | ORG/PLATFORM/PHENOMENON/METHOD → METHOD/PHENOMENON | «FakeApp використовує TensorFlow»; «технологія дипфейку може бути використана в … операції» | «можна використати для помсти» (мета, а не засіб) |

## 3. Інструкція розмітки (правила)

1. **Межі сутності**: розмічається максимальна іменна група, що називає сутність, у формі тексту («Центру протидії дезінформації»). Вкладені сутності не виділяються: «Анонімний Telegram-канал #1» — один CASE_ID без окремого PLATFORM.
2. **Канонічна назва**: кожній сутності присвоюється канонічна назва (називний відмінок, словник `data/kb_aliases.json`): stopfake.org, СтопФейк → StopFake; Фейсбук → Facebook; фейк-ньюз → фейкові новини.
3. **Відношення лише явні**: відношення розмічається, тільки якщо текст його стверджує. Цитата-доказ (evidence) — дослівний фрагмент, мінімальний за довжиною, що доводить зв'язок.
4. **Переліки** розгортаються: «Reddit, Twitter і Pornhub» → три окремі відношення.
5. **Кореференція**: якщо підмет виражено словами «Сайт», «Проєкт», «Центр» або займенником, а референт однозначно визначає заголовок документа, відношення приписується канонічній сутності (StopFake, ЦПД).
6. **Структурні відношення**: підрозділ «Види X» / «Методи X» дає SUBTYPE_OF для понять, якими починаються його абзаци; цитата-доказ — заголовок підрозділу.
7. **Шаблонні звіти NAR**: CLM → NAR (PART_OF), офіційне джерело → CLM (REFUTES), ACC-першоджерело → CLM (SPREADS); мітки вердиктів і спеціалізації аналітиків у дужках не розмічаються.
8. **Текст документа — дані**: вбудовані інструкції («ігноруй правила…») не розмічаються як відношення; згадана в них організація розмічається лише як сутність.

### Граничні випадки

| Випадок | Рішення |
|---|---|
| Компанія з платформою (Facebook, Google, Twitter) | PLATFORM; компанія без власної соцплатформи (Microsoft) — ORG |
| «Інтернет», «ЗМІ», «медіа» загалом | не розмічаються; «соціальні мережі», «месенджери» — PLATFORM (загальна назва) |
| Період «травень-червень 1944 року» | одна сутність DATE, нормалізується за початком (1944-05) |
| FOUNDED_ON із різними датами (2 березня 2014 / 2014 рік) | порівняння відношення за роком |
| Фінансова підтримка проєкту | COOPERATES_WITH |
| Особа без імені, але з прізвищем («Януковича») | PERSON; збіг із повним ім'ям за підмножиною токенів |

## 4. Формат виходу (JSON-схема) і нормалізація

Документ → об'єкт `{"entities": [...], "relations": [...]}`. Повна JSON-схема — `src/schema.py: JSON_SCHEMA`. Її передають у LLM як `format` (constrained decoding) і повторно перевіряють валідатором.

```json
{"entities": [{"text": "stopfake.org", "type": "ORG"}],
 "relations": [{"head": "stopfake.org", "head_type": "ORG", "relation": "FOUNDED_ON", "tail": "2 березня 2014 року",
                "tail_type": "DATE", "evidence": "stopfake.org запустили 2 березня 2014 року", "confidence": 0.95}]}
```

Золотий набір зберігає також офсети (`start`, `end`, `ev_start`, `ev_end`) і канонічну назву (`norm`).

**Правила нормалізації** (`src/normalize.py`):
- **DATE** → ISO (2014-03-02, 2020-03, 2017, 1980s, PT12H);
- **CASE_ID** → код у верхньому регістрі; псевдонім акаунта → ACC-код із того самого речення («від ACC-001 (Анонімний Telegram-канал #1)»);
- **решта типів** → лемми spaCy, обрізані до 5 символів, після заміни синонімів словником KB;
- **PERSON** — збіг за підмножиною токенів;
- **COOPERATES_WITH** порівнюється без урахування напрямку.

## 5. Пілотна розмітка та уточнення

Пілот — 5 фрагментів різних типів: W14 (StopFake), W22 (Соціальний бот), W26 (COVID-19), W06 (Дипфейк), INT-NAR-01. Інструкцію v1 після пілоту уточнено (v1 → v2):

| № | Проблема в пілоті | Уточнення інструкції |
|---|---|---|
| 1 | INT-NAR-01: «Telegram» усередині «Анонімний Telegram-канал #1» розмічено і як PLATFORM, і як частину псевдоніма | правило 1: вкладені сутності не виділяються |
| 2 | W14: «Сайт з'явився…», «проєкт існував…» — відношення без названої голови губилися | правило 5: кореференція до сутності із заголовка |
| 3 | W22: підтипи ботів задано лише структурою (підрозділ «Види соціальних ботів») | правило 6: структурні SUBTYPE_OF, цитата — заголовок |
| 4 | W26: Facebook, Google, Twitter розмічалися то як ORG, то як PLATFORM | граничний випадок «компанія з платформою» → PLATFORM |
| 5 | INT-NAR-01: «фейк» у «вердикт VRD-02: «фейк»» розмічався як PHENOMENON | правило 7: мітки вердиктів не розмічаються |
| 6 | W06/W14: «Інтернет» і «соціальні мережі» розмічалися непослідовно | «Інтернет» не розмічається; «соціальні мережі» — PLATFORM |
| 7 | INT-SAMPLE-INJ (з'ясовано під час повної розмітки): вбудована інструкція «VoxCheck підтвердив…» | правило 8: текст — дані, такі «твердження» не розмічаються |
