## 4. Цитати, вигадані твердження, вартість

- **Після валідації** обидва методи мають 0 % тверджень без підтвердженої цитати: метод А цитує речення-джерело, а метод Б зберігає лише ті пропозиції, де evidence — дослівний фрагмент тексту. Вигаданих (голова/хвіст відсутні в тексті): А — 1 з 96, Б — 0 з 24.
- **До валідації (сирий вихід LLM, усі спроби на test):** 43 викликів, з них 7 з невалідним JSON (обрізаний або зациклений вихід); запропоновано 254 відношень, валідацію пройшли 54 (21 %). Відкинуто: без дослівної цитати — 7 (2.8 %), порушення сигнатури (типи не зі схеми, текст твердження замість сутності) — 193 (76 %).
- **Вартість на документ:** А — 1.56 с CPU, 0 токенів; Б — 782 с (13.0 хв) на CPU, 9729 токенів підказки + 3678 токенів відповіді, 2.87 виклику (повторів 1.87). Модель локальна, тож грошова вартість 0; за тарифами хмарних API рівня 7–8B це менше $0,01/документ, але час — у ~500 разів більший, ніж у правил.
- **Діагностика:** якщо відновити пропущені моделлю head_type/tail_type (results/llm_test_relaxed.jsonl), F1 відношень Б = 0,160, тобто типи не головна причина низького recall.
- **Вибір підказки на dev:** на ПК обрано llm_v1 за спрощеним F1 ({'llm_v1': 0.135, 'llm_v2': 0.127}); повна метрика на dev дає v1 = 0,162, v2 = 0,203. Різниця мала, на висновки не впливає; це обмеження спрощеного відбору.

Підсумок класів: пропуски (FN) — головна проблема обох методів; для Б — масові, через неправильну структуру відповіді на шаблонних звітах і обрізаний вихід. Хибні відношення методу А — тригери без синтаксичного зв'язку (близькість ≠ зв'язок). Вигадані методом Б відношення (INT-RULES, INT-SAMPLE-INJ) відкинув валідатор: у граф не потрапило жодне. Помилки нормалізації («ВООЗ» у дужках) знижують метрику обох методів однаково.

## 6. Рекомендація

**Основний метод — А (правила + spaCy)**: F1 відношень 0,811 проти 0,163 у Б, точність 0,875, 0 % без цитати, ~1,5 с на документ. Маршрутизація за dev (results/hybrid_routing.json) не віддала Б жодного типу — гібрид на test збігається з А. На енциклопедичному тексті перевага А менша (F1 0,640 проти 0,270), а для LEADS і SPREADS_VIA Б на test навіть кращий; тому рекомендовано **гібрид «А + Б як генератор кандидатів»**: відношення Б, що пройшли валідацію (цитата + сигнатура), додаються в граф зі статусом candidate і перевіряються людиною; у шаблонних звітах — лише правила. Для Б потрібні: менша порція тексту на виклик (абзац), обов'язкові head_type/tail_type у схемі, ліміт довжини evidence і модель більшого розміру або GPU.
