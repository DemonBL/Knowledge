# Оптимізація «до/після» (ЛР11, Результат 5)

**Гіпотеза.** Зменшення кількості фрагментів контексту k з 5 до 3 скоротить токени промпту й затримку, не погіршивши faithfulness і правильність, бо reranker ставить доказ угору.

**Змінений фактор:** лише k (5 → 3). Решта — та сама: модель, промпт rag_v1, підграф, суддя, 31 тест.

| Метрика | До (k=5) | Після (k=3) |
|---|---|---|
| Faithfulness | 0.987 | 0.976 |
| Context recall | 0.875 | 0.800 |
| Citation accuracy | 0.662 | 0.731 |
| Abstention (без відповіді) | 1 | 1 |
| Хибні відмови | 0 | 0 |
| Правильність | 0.800 | 0.867 |
| Правильність (виправлена) | 0.867 | 0.933 |
| Pass rate | 0.903 | 0.935 |
| Затримка p50, с | 23.300 | 19.590 |
| Затримка p95, с | 41.410 | 41.670 |
| Токенів промпту (сер.) | 2420 | 1717 |
| Токенів відповіді (сер.) | 77 | 79 |

Вартість: моделі локальні (Ollama), грошова вартість 0 $; як проксі вартості використано кількість токенів (−29 % токенів промпту).

**Висновок.** Гіпотеза підтвердилася частково. Покращилося: токени промпту −29 %, p50 −16 % (23,3 → 19,6 с), правильність 0,867 → 0,933 (T07 тепер містить ключовий факт), citation accuracy 0,66 → 0,73 (менше «зайвих» цитат). Не покращилося: p95 (~41,5 с) — його визначають довгі відповіді, а не довжина контексту; context recall знизився 0,875 → 0,800 (у T10 і T29 доказ випав з top-3), faithfulness судді 0,987 → 0,976. Зміна окупається для коротких фактичних запитів, але для багатокрокових і агрегатних (T10, T15) потрібне k = 5 або більше — тож доцільна адаптивна k за типом запиту.
